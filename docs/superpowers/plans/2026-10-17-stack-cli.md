# stack CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `install.sh`/`sync.sh` with a single static Go binary `stack` that detects installed AI coding agents, generates all rule files in one `.agents/` folder, and symlinks (or copies, for Copilot) only the fixed paths those agents read.

**Architecture:** A thin `cmd/stack` CLI over four internal packages: `generate` (renders `.agents/*` from `AGENTS.md`), `agents` (the registry of 8 agents with their fixed paths), `detect` (PATH/home/VS-Code-extension detection behind a `Finder` interface), and `project` (install/sync/check/uninstall against one project root). The repo root embeds the shipped template files via `go:embed`, and the repo dogfoods its own tool: its root config files become symlinks into `.agents/`.

**Tech Stack:** Go 1.27, charmbracelet bubbletea + lipgloss for the table UI and confirm prompt. No other direct dependencies. Tests are plain `go test` with fakes and temp dirs.

**Spec:** `docs/superpowers/specs/2026-10-17-stack-cli-design.md` — the plan argues from the spec; executors read both.

## Global Constraints

- Module path `github.com/MDC15/stack-agents`; Go 1.27; direct deps limited to `charmbracelet/bubbletea` and `charmbracelet/lipgloss`.
- CLI messages in English; identifiers in English.
- Banner string is exactly: `<!-- Generated from AGENTS.md by stack sync. Edit AGENTS.md, not this file. -->`
- Agents are exactly the eight in spec §2 (claude, opencode, codex, cursor, copilot, cline, roo, windsurf) with the fixed paths and detection signals listed there.
- All six `.agents/*` files are generated on every sync regardless of detection; links are created only for detected ∪ opted-in agents (`--agents`, `--all`, or an existing link/copy at the fixed path).
- `.github/copilot-instructions.md` is always a banner-carrying copy; every other fixed path is a relative symlink with copy fallback.
- Nothing is written outside the target project root.
- Exit codes: 0 success, 1 drift/failure, 2 usage error (matches the scripts being replaced).
- `scripts/load_skill.py` keeps its path and behavior; it is still shipped into projects and still covered by a test (skip when `python3` is absent).
- Docs: `docs/en` ↔ `docs/vi` parity (same filenames, same heading counts) and relative-link integrity stay enforced by tests (ported from `scripts/test.sh`).
- `VERSION` ends at `1.0.0` with a `CHANGELOG.md` entry.
- Uninstall safety: remove only symlinks resolving into `.agents/`, banner-carrying files, and files enumerated in the embedded assets; never user-owned files.

## Review Focus

1. **Nested relative symlink target** — `.cursor/rules/stack-agents.mdc` is two directories deep; its target must be `../../.agents/cursor.mdc`. A wrong relative path silently breaks Cursor. Pinned by the Readlink assertion in Task 5.
2. **`--force` AGENTS.md merge without the `## Project overrides` heading** — defined behavior: if the target's AGENTS.md lacks the heading, overwrite it entirely and warn. Pinned by two Task 6 tests (heading present / absent).
3. **Symlink creation failure must fall back to a banner-carrying copy, and `check` must accept that copy** — this is the Windows story. Pinned by the injected-`Symlink` tests in Task 5.
4. **Uninstall must not touch user-owned files** — a user's own `.clinerules` (no banner), `.ai/conventions.md`, and custom skills survive. Pinned by Task 6 tests.
5. **Embedded asset set vs uninstall's shipped set** — uninstall deletes exactly the files the embed ships; if the two drift, updates orphan files. Pinned by the asset-enumeration test in Task 1 reused by Task 6.
